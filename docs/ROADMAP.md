# ANEK.: план движка, сериала и игры

Статус: этапы 1–5 сделаны (отчёты: [stage-1](reports/stage-1/README.md), [stage-2](reports/stage-2/README.md), [stage-3](reports/stage-3/README.md), [stage-4](reports/stage-4/README.md), [stage-5](reports/stage-5/README.md)); дальше этап 6.
Принцип: LLM пишет только текст — сценарий анекдота, связки серии, арку. Всё остальное — детерминированный код и данные: постановка, раскладка, камера, рендер, проверки. Масштабирование почти не должно тратить токены.

## 5. Скомпилированный эпизод: `performance.json`
- **Сделано** ([отчёт](reports/stage-5/README.md)): компилятор `remotion/src/perf/compile.ts`, `pnpm compile-episode [--check]`, проигрыватель `perf/Play.tsx`; кадры совпадают с прежней постановкой. Типы и `sample` лежат в `remotion/src/perf` (чистый TS) — на этапе 7 переезжают в `packages/player`.
- **`pnpm compile-episode <id>`.** Эпизод и озвучка превращаются в явный трек по времени в секундах, не в кадрах:
  ```
  { v, id, locale, duration, scenes: [{from, to, location, place, transition}],
    actors: {id: {look, tracks: {x, z, seated, pose(base/act/k), facing, emotion, mouth, hold, riding}}},
    vehicles, props (лежащие), camera: [{t, scale, fx, fy}], captions: [{from, to, text, words}],
    audio: [{t, file, gain, rate}], signs: locale }
  ```
  Треки — ключевые точки с интерполяцией; рот — по таймингам слов.
- **Remotion только проигрывает трек.** Логика постановки на каждом кадре уходит из `Joke.tsx` в компилятор: тот же `timeline.ts` и `stageGeometry`, но запускаются один раз.
- **Сломаться может:** точность движения (интерполяция ключей вместо вычисления на каждом кадре). Проверка — golden: дифф кадров до и после.

## 6. Сценарии: дёшево и предсказуемо
- **Ограничения для сценариста.** В схеме ответа — только существующие куклы, роли, места, сублокации, метки, реквизит, действия и машины (enum из реестра). Сейчас это проверяется после записи, станет проверяться при записи.
- **Линтер сценариев без LLM** (`pnpm lint-scripts`):
  - в реплике упомянут персонаж («это моя жена»), которого нет на экране, хотя в cast есть место;
  - реплика длиннее трёх строк субтитров;
  - у куклы нет голоса для этого языка;
  - метка-сиденье занята двумя;
  - машина перекрывает говорящих;
  - действие стоит не перед репликой, которая его называет.

  Что исправляется по правилам, исправляет код. LLM переписывает только эпизоды, не прошедшие линтер.
- **Промпт** обновляется по мере появления возможностей (уже: глубина, комнаты, сиденья, транспорт, форма).

## 7. Плеер трека: `packages/player`
- **Пакет без Remotion и React:**
  - типы `performance.json`;
  - `sample(perf, t) → FrameState`: чистая функция, где кто стоит, поза, рот, камера, субтитр, какие звуки играют.
- **Отрисовка — отдельными обёртками:**
  - `remotion` — `FrameState` → React SVG (текущий арт);
  - `web` — тот же React SVG в браузере, Tauri и мобильном webview, звук через WebAudio;
  - позже `pixi` для игры.
- **Арт для Pixi.**
  - Фоны статичны. Шаг `pnpm export-art` растеризует каждый слой (`back`/`front`) каждой сублокации и языка в PNG/SVG-атлас и пишет рядом метаданные: метки, сиденья, поверхности, передний слой.
  - Куклы: из данных этапа 4 (слоты + примитивы) строится display list — путь, эллипс, трансформ. Его одинаково рисуют SVG и Pixi Graphics.
- **Мешает сейчас:** хуки Remotion в риге (решается в этапе 4) и время в кадрах (решается в этапе 5).

## 8. Мир: канон, состояние, карта
- **`content/world/canon.json`** — библия сериала, её читают сценарист и игра.
  - **Кварталы** (`districts`): общий центр, «русский», «английский», «немецкий» кварталы. Культурно-специфичные анекдоты живут в своём квартале того же города.
  - **Жители** (`residents`): кукла, имя на каждом языке, квартал, дом (`location:place`), работа (место и роль), характер, повторяющиеся шутки.
  - **Отношения** (`relations`): `{a, b, kind}` — муж/жена, сосед, начальник, собутыльник, тёща.
  - **Постоянные места**: бар «у Петровича», поликлиника, отделение.

  **Связь с анекдотами.** Роль в анекдоте → житель канона. Например, everyman в браке → муж из семьи Петровых, если в анекдоте есть жена. Подбор детерминированный (`pnpm canon-cast`). Анекдот, который противоречит канону (у холостяка жена), в сериал не идёт или получает другого жителя.
- **`content/world/state.json`** — состояние мира: журнал событий серий (`{series, episode, fact, actors, place}`). Примеры фактов: «у Петровича разбита машина», «Вовочка остался на второй год». Сценарист связок получает выжимку фактов про участников серии. Линтер проверяет противоречия: факт «машина разбита» → без машины до факта «починил».
- **Карта как граф** (`town.json` → `content/world/map.json`): узлы — здания и улицы с координатами и кварталом; рёбра — переходы (дверь, улица, транспорт), время пути; у здания список мест и сублокаций.
  - Пролёты в сборниках идут по графу, а не по прямой.
  - Новая локация = узел и рёбра в данных, без кода.

## 9. Сериал
- **Серия** — несколько готовых анекдотов (с их озвучкой, без изменений), общая арка и связки между ними.
- **`content/series/<id>.json`:**
  ```
  { id, locale, title, district, arc: {premise, goal, turn, ending},
    parts: [ {kind: "bridge", scenes: [...], lines: [...]},          // связка: свои сцены и реплики, озвучка как у эпизода
             {kind: "joke", episode: "ru-…​.ru"},                   // анекдот как есть
             … ],
    cast: {residentId: puppetId}, stateChanges: [{fact, actors}] }
  ```
  Связка — эпизод формата `bridge` с теми же сценами, битами и озвучкой. Рендер серии = сборник (`Compilation`) с частями.
- **Подбор анекдотов — код, не LLM:** общий квартал или места, общие жители по канону, разные локации, без противоречий состоянию.
- **LLM-стадия `series`** (`pipeline/prompts/series.md`). Вход: канон (выжимка про участников), состояние мира, 3–5 анекдотов (место, роли, первая и последняя реплика, суть). Выход: арка, 2–6 связок (сцены и реплики), изменения состояния. Проверка — `sceneProblems` и линтер.
- **Оценка токенов на одну серию из 4 анекдотов:**

  | Что | Токены |
  |---|---|
  | Вход: промпт | ~3k |
  | Вход: выжимка канона | ~4–6k |
  | Вход: состояние | ~1–2k |
  | Вход: 4 анекдота | ~4–6k |
  | **Вход всего** | **~12–17k** |
  | Выход: арка и 4–5 связок по 2–5 реплик со сценами | ~3–5k |
  | Прямой вызов модели | ~15–22k |
  | Через сабагентов Claude Code (накладные расходы на чтение файлов, пачка из 4–5 серий на агента) | ~30–40k на серию |

  Озвучка связок: 300–800 знаков на серию. Сами анекдоты не переписываются и не переозвучиваются.

## 10. Мемы
- **`content/memes/<id>.json`** — формат-шаблон:
  ```
  { id, country: "ru|en|de|…", style: "reaction|situation|expectation-reality|chat|local",
    structure: {characters: 2, form: "panels"|"scene", panels?: [{who, caption, act}], punchline: "last-panel"},
    fits: {roles: [...], places: [...]}, origin: "<ссылка для нас, не для показа>", risk: {...} }
  ```
- **Как разыгрываются.** Нашими куклами в нашем городке. Чужие картинки, кадры из фильмов, лица реальных людей и персонажи чужих франшиз не используются: берём только идею формата.
- **Эпизод** `format: "meme"`. Новый тип сцены `panels`: 2–4 стоп-кадра с подписями. Кадр — обычные биты, застывшие в позе; подпись — сверху или снизу, переход — щелчок. Для «переписки» — сцена-чат (пузыри поверх кадра).
- **Стадия `risk` для мемов:**
  - отсылка к реальному человеку → `exclude` или замена на жителя городка;
  - политика → `exclude`;
  - чужая франшиза → только формат, без персонажей и узнаваемых кадров.
- **Мемы в сериале и игре:** «повторяющиеся шутки городка» (`canon.residents[].gags`) и события, где житель «живёт» мемом.
- **Сейчас:** только схема и место в плане, без реализации.

## 11. Игра (ориентир — исследование городка в духе South Park: The Stick of Truth)
- **Что войдёт:**
  - 2D-прогулка по графу города;
  - вход в локации (сублокации — комнаты);
  - разговоры с жителями (реплики канона);
  - запуск анекдота там, где он «живёт» (место + жители);
  - коллекция открытых анекдотов и мемов.
- **Что закладываем сейчас, чтобы не закрыть дорогу:**
  - время в секундах (этап 5);
  - плеер без Remotion (этап 7);
  - арт с временем-пропсом (этап 4);
  - локации с метками, сиденьями, поверхностями и слоями в данных (уже);
  - карта-граф (этап 8);
  - канон жителей (этап 8);
  - надписи по языкам (уже).
- **Мешает игре сейчас** (отмечено, решается этапами):
  1. Фоны нарисованы под вертикальный кадр 1080×1920. Для прогулки нужны широкие панорамы. Решение: у места параметр ширины (уже есть `stageW` для широкой сцены), новые и перерисованные фоны рисуются тайлами по ширине; вертикальное видео — окно камеры над широкой сценой.
  2. Камера рассчитана на вертикальное видео. В игре своя камера (следит за героем); трек камеры — только для роликов.
  3. Куклы видны только в профиль/три четверти. Ходьба вверх и вниз по экрану в игре — тем же профилем со сменой глубины (z): это как раз South Park, менять не нужно.
  4. Звук привязан к кадрам Remotion (`<Sequence>`). В плеере — WebAudio по секундам.

## Порядок работ и правила
1 → 2 → 3 → 4 → 5 → 7; параллельно 6 и 12; 8 → 9 после 5; 10 и 11 — только схемы.

После каждого этапа:
- typecheck, `pnpm validate`, `pnpm golden`;
- короткий отчёт со стоп-кадрами до и после;
- небольшие коммиты в ветку;
- push только по просьбе.

Ограничения:
- LLM-прогон больше 20 эпизодов — только после оценки токенов и «да» пользователя.
- Платная озвучка — только с согласия; для отладки — `--provider fake` или уже озвученные реплики.
- Арт рисуется только кодом.
