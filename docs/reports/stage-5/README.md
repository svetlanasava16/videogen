# Этап 5: скомпилированный эпизод (performance.json). Отчёт

План: [docs/ROADMAP.md](../../ROADMAP.md), §5. Справочник: [docs/ENGINE.md](../../ENGINE.md), §11а.

## Сделано
- **Компилятор** `remotion/src/perf/compile.ts`.
  - Прогоняет по всем кадрам ролика таймлайн, геометрию сцены и камеру. Раньше это делал `Joke.tsx` на каждом кадре рендера, теперь — один раз.
  - Результат — `performance.json`: треки по времени в секундах (формат — `perf/types.ts`):
    - сцены и виды (половины разделённого экрана): место, ширина сцены, передний слой, массовка, мебель, лежащие предметы, тряска, камера;
    - куклы — облик и треки: на сцене / в машине / нет, бокс, план, ходьба, сидит, в кровати, вздрагивает, куда смотрит, говорит, эмоция, предмет в руке, жест и состояние с силой и началом;
    - машины и седоки;
    - субтитры со словами (караоке) и озвучкой;
    - звук: музыка, смех в конце, эффекты, закадровый смех.
- **Геометрия сцены** вынесена из `Joke.tsx` в `stage/geometry.ts` без изменений. Это чистый TS: работает и в браузере, и в Node.
- **Проигрыватель** `perf/Play.tsx` рисует кадр только из треков, без логики постановки. Звук — `perf/PerfSoundtrack.tsx`.
- **`Joke.tsx`:** было 610 строк, стало 30 — скомпилировать (с кэшем) и проиграть. Новая композиция `Performance` проигрывает готовый `{perf}`.
- **`pnpm compile-episode <id>|--debug|--all [--out out/perf] [--check]`** — команда компиляции.
  - `--check` сверяет треки с покадровой постановкой на каждом кадре каждой куклы. На всех 1 805 эпизодах (2,6 млн кадров кукол) расхождений нет.
  - `pnpm render` компилирует в Node, кладёт `renders/<id>/<hash>.performance.json` рядом с видео и рендерит композицию `Performance`.
- **Скорость и размер:** все 1 805 эпизодов компилируются за ~13 с, вместе весят 21 МБ (~12 КБ на эпизод).
- Шрифт грузится только в браузере (`fonts.ts`), чтобы компилятор работал в Node. `jsx` включён в tsconfig пайплайна.

Пример: жена в «Толкнуть», первая сцена. Пока она лежит, у каждого трека один-два ключа:
```json
"x":       { "t": [0, 5.366667], "v": [734.4, 734.4] },
"bed":     { "t": [0, 5.366667], "v": [1, 1] },
"act":     { "t": [0], "v": [null] },
"speaking":{ "t": [0], "v": [false] }
```

## Точность: кадры совпадают с прежней постановкой
Первая версия хранила треки с прореживанием (ошибка ≤ 0,01 px). Golden проходил, но строгая проверка нашла три расхождения:
- **Порядок отрисовки.** Старик и гаишник стоят на «одном» плане: z = 0,1 и 0,09999999999999998. Кто нарисован поверх, решал этот шум в последнем бите. После округления z до 1e-5 порядок поменялся, и жезл ушёл за спину старика. Решение: z хранится точно.
- **Время позы.** `t` жеста хранился линейным треком и между ключами давал 0,3999988 вместо 0,4, а покачивание головой на это чувствительно. Решение: хранится начало жеста (ступенька), `t = (кадр − начало) / fps` считается в проигрывателе — как в постановке.
- **Камера и позиции.** Наезд на панчлайне выходил с ошибкой масштаба ~1e-8. Это давало 1–2 пикселя разницы в сглаживании. Решение: все числовые треки точные — ключи только там, где значение меняется. Размер вырос на 20 % (16 → 21 МБ на все эпизоды).

**Итог:**
- кадры отладочного набора в полном разрешении совпадают с кодом этапа 4 **бит в бит** (проверено на 9 кадрах, где расхождения были);
- в уменьшенных кадрах (stills ×0,25) совпали 393 из 401 — остальные 8 в полном разрешении тоже бит в бит, разница только в растеризации при уменьшении;
- `pnpm golden:docker` — 24 из 24 совпали с эталонами.

## Что это даёт дальше
- Плеер этапа 7 (`packages/player`) берёт `perf/tracks.ts` и `perf/types.ts` как есть: это чистый TS без React и Remotion. Для веба формат допускает прореживание с погрешностью (`encodeLin(…, eps > 0)`), если понадобится меньше размер.
- Новая логика постановки пишется в компилятор (geometry, timeline, camera), а не в проигрыватель.

## Открыто
- Субтитры, переходы, пролёты и массовка пока берут кадр через `useCurrentFrame` (обёртки Remotion). Для плеера их нужно перевести на время пропсом, как куклу (этап 7).
- Сборник (`Compilation`) компилирует каждый эпизод в браузере. Это быстро (~50 мс на эпизод), но можно передавать готовые треки.
